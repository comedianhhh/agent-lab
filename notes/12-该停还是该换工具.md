# 12 · 该停还是该换工具（2026-11-18）

对照 Agent Reach `runtime/dispatch.py` 的 `run_action`，并在 jobs-mcp 里实现了 LinkedIn 备选后端（`mcp/jobs-mcp/jobs_mcp/fallback.py`）。

1. **换工具**：出错的是这一条路、不是目标本身时才换。比如 `UPSTREAM_BROKEN`（对方 5xx、断网）或 `TIMEOUT`，换个后端很可能就成功了。
2. **停：被限流**（`RATE_LIMITED`、LinkedIn 999）。网站在挡这台机器，换一条路去访问同一个网站只会被封得更狠。jobs-mcp 遇到 429 不会去调 Agent Reach。
3. **停：要登录**（`NEED_LOGIN`）。换个工具也绕不过登录，只能让用户自己去登录或贴原文，agent 不能替用户输密码。
4. **停：参数错**（`BAD_INPUT` / `NOT_FOUND`）。换什么工具，同样的参数都会错，要先改参数。
5. **为什么分得这么死**：工具返回 `retryable` 和一句 `hint`，agent 只要看错误码就知道下一步，不用读报错原文自己猜。也避免了死循环重试，或者把一个被限流的网站越打越狠。
